# Workflow evidence consolidation — 19 November 2026

> Current scope: the six table replacements remain, while the extra action engine has been removed. Dedicated compatibility views/procedures are unnecessary. See [the retained architecture and validation](production-table-storage-consolidation-2026-11-19.md).


This follows the [stock posting consolidation](stock-posting-entity-consolidation-2026-11-19.md). It replaces `tbl_ProjectHandover`, `tbl_ProductionReadiness` and `tbl_ProductionStartNotice` without introducing replacement tables. Subscription proposal storage remains unchanged.

## Existing functionality reused

**Final handover:** a protected Memo on the exact issued package version holds the original record ID, project/share, actor, timestamp and complete snapshot. `vw_ProjectHandover` is a read projection. Old IDs and every original column are retained. Copied package versions do not create another handover: evidence is bound to its original entity/version. The existing native evaluator still checks scope, pins, production/receipt completion, responsible groups, current client response states, recipients, fixed share and whole-package acknowledgement before recording. Concurrent retries return the original record; a different share requires an amendment package.

**Readiness:** the last published result is a read-only Memo on the checked production-order version. `vw_ProductionReadiness` projects the latest publication, using a per-order publication sequence rather than wall-clock timestamps. Changing mappings, creating a new order version or correcting the clock cannot revive an older decision. Every actual readiness check still recalculates the current project, stock/reservation/issue coverage, predecessors, holds and documentation. Publishing retains the existing internal-Editor and evidence-access requirements. Legacy report text, decisions and timestamps are preserved; the original cache did not store its checked version, so that value remains unknown instead of being invented. Migrated reports are attached to the order's current version for storage. New publications record the checked version explicitly.

**Start warnings:** shared `AutomationCheckpointStore` uses existing workspace setting storage for a durable checkpoint per order/planning activity/local start time. First and latest warning UTC timestamps remain intact, including fractional start-time precision. Existing persistent event execution claims reserve a deterministic initial-event identity. IDs use the first 16 bytes of SHA-256 over the UTF-16LE workspace/scope/schedule/occurrence key; SQL migration and application code agree. Checkpoints, readiness publication and outbox appends share the caller's serializable transaction. Initial warnings are not resent after migration or event-history cleanup. Changed schedules and configured blocked-repeat intervals retain their existing behavior. Consent and access checks in routing/delivery remain unchanged.

## Administrator configuration and protection

**Configuration → Workspace Defaults → Workflow evidence** selects distinct enabled Memo properties for handover and readiness. Custom properties must be assigned read-only to the appropriate categories. Default properties are seeded once and assigned to configured categories, with the existing panels presenting the user-facing information. Categories and Property Definitions control names, descriptions and visibility. Reruns preserve custom mappings and labels; historical reads do not depend on the current mapping. Existing automation parameters retain all warning timing, state, scope, wording and workflow choices.

Database guards prevent forged or rewritten version-bound evidence through ordinary property writes. Handover package evidence, project and share cannot be removed through ordinary deletion. Readiness updates go through the trusted publisher. Authorized whole-workspace purge remains supported. Temporary writer/purge session permissions restore their previous value on success, failure and cancellation; an unusable connection is discarded rather than returned with elevated session state.

## Migration and validation

Deploy `20261119_workflow_evidence_consolidation.sql` with API/background workers stopped. The script validates entity/version/workspace/share relationships, preserves complete original rows under `Legacy`, converts notices and execution claims, verifies results and removes the old tables in one data transaction. Conflicting destination checkpoints or invalid relationships abort conversion. It does not publish events, create subscriptions, post stock or change stock positions. Repeating the migration preserves evidence and administrator configuration.

A COPY_ONLY backup with checksums was verified and restored into an isolated local database. The rehearsal converted **four handovers, 12 readiness results and three start-warning records**. All original projected fields compared unchanged, with binary comparison of the large handover/report strings. Stock positions and ledger rows also compared unchanged. Three persistent initial-warning claims were added. An authorized workspace-purge rehearsal passed and was rolled back.
